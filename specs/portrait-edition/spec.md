# One Sky, Many Stories — 縦読み版の制作仕様

## 読書体験と原本

iPhoneを片手に、読者が星を見つけ、人物と一緒に空を見上げ、英文を声に出して読める縦スクロール絵本を作る。主対象は393 × 852 CSS pxの縦画面。20場面それぞれに描き下ろした縦構図を使う。iPhoneを横に回しても、iPadやPCで開いても、同じ絵と英文が縦一列に続く。広い画面では中央に絵の原寸比を保つ読書幅を設ける。主絵の取得に失敗した場合は同じ縦絵の縮小版を表示する。

本文の正本は原本PDFの20ページ。Web版では [story.json](../../src/data/story.json) の英文を、一字ずつ原順のままHTMLに一度ずつ置く。句読点、引用符、三点リーダー、Shōnagon、Māori、Papatūānukuを保つ。縦絵の演出情報は場面IDで結び、PDFの再抽出後も使えるようにする。挿絵は内蔵画像生成で制作し、WebPで配信する。

原作資料は制作プロジェクト `one_sky_many_stories` 内の `specification.md`、`sources.md`、`storyboard/pages.json`、`storyboard/page_prompts.md`、`output/quality_report.md`。顔・衣装は `assets/` の3人の設定画、光と筆致は `night_style_ref.png`、前後の人物・小道具・時間帯は完成した横長原画を参照する。以下は縦版の設計と検証条件である。

## 連続縦読みと読み聞かせ

- ページを開くと、そのまま人が声に出して読める。絵と英文を一続きの縦の紙面に配置し、指を少し動かせば絵も英文もその分だけ移動する。自由な途中停止、逆読み、端末の慣性スクロールを保つ。必須の開始操作、ページ単位の吸着、合成音声による朗読は設けない。
- 風景や星空、余白を前後の場面の間に置く。境界の中ほどでは、前の場面を読み終える人に次の場面の入り口も見える。各場面の高さは絵と文章量に従う。英文は正本の順序で選択可能なHTMLとして配置する。
- 第7・8・11場面は自然な本文のまとまりを二つに分ける。第7は祖母の問い→星を数える絵→ `Luna counted them slowly.`。第8は丘の望遠鏡と説明→暗い星まで見える視野と `“Some are hard to see`。第11はルナの問い→七姉妹→ `“In one version of the story,`。読む人が下へ送るにつれ次の文が紙面に現れる。時間の経過だけで答えは進まない。
- 望遠鏡はのぞき込む方向へ寄り、回想や神話では元の景色の中から次の景色が浮かぶ。第11でスクロールを止めるとカメラと人物も止まり、髪・袖・雲だけが一拍揺れて静まる。第9→10の丘は同じ稜線に連ねる。途中停止でも七姉妹が二組に見えないようにする。
- 動きを減らした設定でも同じ順序で、全英文と場面の発見をたどれる。画面外・バックグラウンドで継続描画を止める。文字拡大時は自然な改行と文書の伸びで全文を見せる。タイトルはCormorant Garamond、章題はCinzel、本文はLora。人物の顔、指先、数える星を本文や端末の切り欠きと重ねない。

## スクロールで動く挿絵

画面位置を動かすのは読者の指とブラウザの慣性。Safariのアドレスバーが伸縮しても、絵と本文は惰性で一緒に進み続ける。どこで止まり、どれだけ速く通り過ぎるかも読者が決める。絵の動きは同じ位置で同じ姿に戻る。第11場面の髪・袖・雲と第12場面の紙端・反射には、動きが止まった後の短い余韻を持たせる。

動作軽減中や原寸画像を取得できないときは静止絵で同じ英文を読める。動作確認では、縦原画に対する位置ずれ、人物や星が二重に見える箇所、逆送りで姿が飛ぶ箇所を調べる。Safariの慣性は指を離した後のスクロール位置、英文と絵の画面上の移動、アプリからの位置の書き戻しを合わせて検証する。

## 素材と検収

- 画風は深い藍とラベンダー、金色の提灯、手描きの線と柔らかい山並み。Lunaは桜の髪飾りと象牙色のケープ、Leoは茶髪・オリーブ色のケープと青い神話の本、Noahは暗い巻き髪・紺のマントと星の手帳。人物が映る別原画では髪・衣装・持ち物・視線を照合する。主絵には場面を表す代替テキストを持たせ、重なる装飾・効果には重複した説明を付けない。
- 第7の「6」はLunaがその晩に見た数。第8の望遠鏡は淡い星まで見えることが要点。星団は小さく不規則に集まる。第9〜11の七姉妹と第15〜16の母と娘はそれぞれの伝承の人物として描き分ける。第13・14・15の地域や伝承を限定する英文を保持し、新たな儀礼や記号を衣装・背景に加えない。
- 原本由来の照合データと実際のDOMの全文を全20場面で比較する。二拍の場面も一続きの原文を得られること、問いで指を止め、次の英文まで滑らかに送り、逆にたどったとき正しい文と絵が同じ位置にあることを確かめる。全19境界は前後両方を写した途中画面でつながりを目視確認する。
- Production BuildをPagesのサブパスで開き、WebKitの393 × 852で全20縦絵の取得・デコード・静止読書位置を確認する。横画面、PC、短い横長ウィンドウでも全20枚の縦原画と実寸比を確認する。第5場面は「Subaru」の題、上の桜と星、下のルナ・祖母・縁側を縦にたどれることを見る。新たな接眼像や効果レイヤーも配布物に含まれ、参照がすべて解決することを試す。
- 全20場面の画面写真を並べ、構図・人数・季節・明暗・英文との一致を確認する。第7・8・11は両拍、第10・11・15・16は人数、第17は全文と200%文字拡大、第20は最終文の余白を個別に点検する。通常文字の背景とのコントラスト比は4.5:1以上を目標とし、場面切替中の顔や強い光が本文を横切らないかも見る。
- 順読み・逆読み、画面高の変動、静止設定への切替、Canvasや追加素材を利用できない時も読む。縦横回転、横はみ出し、画面外の描画・初回の一括取得、コンソール・HTTPエラーを検査する。実機の操作感・セーフエリア・発熱と、エミュレーションで検証できた項目は報告時に区別する。
