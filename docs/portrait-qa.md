# 縦スクロール版の検証

絵本を開くと、20場面の絵と英文が一本の縦スクロールでつながる。読み手は自分で声に出して読み、好きな箇所で立ち止まって元の絵や台詞へ戻れる。第7・8・11場面は二つの読書位置を持ち、全体で23箇所の英文を検査する。

## 読書画面での確認結果

2026年11月26日、iPhone・iPad相当のWebKit 27.2とデスクトップのChromium 159で本番ビルドを検査し、69件すべてが成功した（約1分）。配布物は80ファイル、16,011,885バイト。縦版では20場面の全英文が原本と一致し、本文を23箇所で読めた。縦の20枚、祖母の回想が始まる前の夜空、望遠鏡の視野、無人の稜線は、配信されたWebPのSHA-256がローカル原画と一致した。横画面でも20枚すべてのPDF由来の挿絵を照合した。

| 縦画面 | 検査した英文 | 本文の最低コントラスト | 比較した行背景の画素数 |
| --- | ---: | ---: | ---: |
| iPhone 16相当 · 393 × 852 | 23箇所 | 14.58:1（第4場面） | 643,884 |
| iPad Pro 11相当 · 834 × 1194 | 23箇所 | 14.10:1（第4場面） | 909,009 |

上下に動かしたとき、絵と英文は標準スクロールの移動量に対して2 CSS px以内で追従した。第9場面の英文がまだ見えているうちに第10場面の稜線を眺められる。第7・11場面の問いで90秒相当静置したあとも、読んでいる位置と次の答えの順序を保持した。発声、音声再生、録音の呼び出しは全編で0件。200%の文字サイズでも第17場面の長文は横にはみ出さず、通信断の第12場面は接続が戻ると同じ位置で原画を再表示した。

iPhone・iPadの全20場面の画面写真と分割された答えを目視し、星を見上げる人物、台詞の改行、前後の絵のつながりを確認した。iPhoneの表紙はSafariのバーを広げると冒頭が隠れていたため、タイトルを絵の上の空に重ねた。修正後はiOS 26.5のiPhone 16 Simulator上のSafariで、登場人物3人と冒頭の段落全体が初期画面に収まった。上下のバーを見込んだ393 × 700 CSS pxのWebKitでも、第一文の下端は画面上端から638 pxだった。[iPhoneの表紙](screenshots/iphone-01.webp)・[第9場面から第10場面の途中](screenshots/iphone-09-to-10.webp)・[デスクトップの冒頭](screenshots/desktop-opening.webp)

Chromiumで下り1.6 Mbps、遅延設定150 ms、キャッシュを空にしたローカル配信を各3回測定した。表紙に先に帯域を割り当てる変更で、表紙をデコードするまでの中央値は8.16秒から5.04秒になった。冒頭の英文はいずれも約2.5秒で表示された。次の場面の先読みは表紙の読込完了・失敗・読者の最初のスクロールのいずれかで始まる。実回線では配信側の圧縮、通信速度とキャッシュによって所要時間が変わる。

## 紙面を止めたところで見る

第4場面は空の右上に祖母の姿が浮かび、第10場面は同じ稜線に七姉妹が現れる。画像の原寸上で位置を揃え、半分だけ送って指を止めても前景がずれないことを確かめた。第11場面ではルナの問いの先で七人を眺め、さらに送るとレオの答えを読める。[第4場面の途中](screenshots/iphone-04-memory.webp)・[第10場面の途中](screenshots/iphone-10-myth.webp)・[七姉妹の場面](screenshots/iphone-11-sisters.webp)

iOS 26.5のiPhone 16シミュレーターでMobile Safariを起動し、画面上の連続ドラッグで23箇所をたどった。Safariのアクセシビリティ表示から取得した23個の英文は、句読点を含めてPDFと一致した。第11場面からホーム画面に出て戻り、同じ英文が同じ位置に残ることを確認した。iPad Air 11のシミュレーターでも全23箇所の英語と逆読みを調べ、分割表示と縦横回転を確認した。さらにSafariのページメニューで100%から200%まで5段階に拡大し、同じ5段階で100%へ戻しても、第17場面の英文を読み続けられた。200%でも指で前後に送れた。第11場面で別の文書に移動して「戻る」を押し、続けて再読み込みした実測では、3回ともレオの答えの上端が847 ptにあった。

## 再現方法

```sh
npm ci
npx playwright install chromium webkit
npm run typecheck
npm run build
npm test
```

テストは配布用の `dist/` をGitHub Pagesと同じ `/one-sky-many-stories/` にマウントする。iPhone 16相当のWebKit（393 × 852）、iPad Pro 11相当のWebKit（834 × 1194）、デスクトップChromium（1440 × 900）を起動する。[ブラウザ設定](../playwright.config.ts)

公開後は対象リビジョンのファイルが手元にある状態で、次のコマンドを実行できる。ブラウザはログイン情報や保存済みキャッシュを持たない新しいコンテキストで公開URLを開く。

```sh
PLAYWRIGHT_PUBLIC_URL=https://belltreetech.github.io/one-sky-many-stories/ npm test
```

## 何を確かめるか

- **絵と英文を同じ指の動きで読む。** 主絵と本文が動いた距離をブラウザのスクロール量と比較し、任意の途中位置で止まることと、戻った時の構図を確かめる。Chromiumではホイールに加えてブラウザの入力プロトコルからタッチ開始・移動・終了を送り、標準のスワイプを動かす。モバイルWebKitではハードウェアキーボードによるネイティブスクロールを検査する。
- **場面がつながる。** 第9・10場面の境界を画面の途中に置き、両方の場面に属する絵または英文が同時に見えることを確かめる。青い本で語られた風景のあと、同じ稜線に七姉妹が現れる。第4場面では祖母の記憶が元の夜空の右上だけに浮かぶ。第8場面では丘と望遠鏡の中が文書順に見え、第11場面では読者が止めたカメラと、髪・袖・雲に残る短い動きを別々に測る。[縦絵の検査](../tests/portrait.spec.ts)
- **読み手が声に出す。** 開いた直後に本編があること、開始・ページ操作・音声のボタンを必要としないことを確認する。発声・音声再生・録音機能を備えた端末の条件を模し、全編をたどって呼び出しが生じるかを調べる。音声APIが使えない環境でも、第7・11場面の問いで90秒相当待ち、同じ位置に留まること、手で送ると答えを読めることを確かめる。[読み聞かせの検査](../tests/read-together.spec.ts)
- **原文・原画・アクセシビリティ。** PDFから独立に抽出した英文と実際のDOMを全20場面で照合する。画像を実ブラウザでデコードし、縦横の選択、画像説明、種類、解像度、配信バイトのSHA-256を検査する。WebPを取得できない時の代替、通信復帰、Canvasを使えない場合、200%の文字拡大、縦横回転、動きを減らす設定での通読にも検査を設ける。[PDF照合データ](../tests/fixtures/pdf-oracle.json)・[全編のテスト](../tests/reader.spec.ts)
- **英文のコントラスト。** 読書位置で文字を一時的に透明にし、画像、グラデーション、半透明レイヤーの合成後の画素を取得する。実際の文字色と各行の背景のコントラスト比を算出し、最小値が4.5:1以上かを判定する。行の内側の空白も対象とし、文字のアンチエイリアスは計算に含めない。[測定コード](../tests/readability.ts)

画面写真とコントラスト測定値はローカル実行では `artifacts/webtoon-qa/screenshots/`、公開URLでは `artifacts/public-webtoon-qa/screenshots/` に出力する。物理端末の切り欠き、指に伝わる感触、長時間の発熱・消費電力は、エミュレーションとは別の確認事項となる。
